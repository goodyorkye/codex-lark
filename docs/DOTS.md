# 同一个飞书机器人连接原 Dot 会话（实验功能）

在飞书点“切换到 Dots / 返回 Codex”，共用现有机器人和长连接。Dots 不放入本地项目列表。切换保留 Codex 的项目、任务、模型、组合输入、排队输入和正在执行的工作；已经发出的 Dots 问题在返回 Codex 后仍会回复原飞书消息。

此功能直接使用本机已登录 ChatGPT 客户端的原 Dot 会话。文字、原始图片、文件、音频和 Dot 答复保存在同一个原生消息房间，客户端可以读取这些原会话记录。Dot 仍运行在云端，电脑需要能访问 OpenAI；“本地直连”不代表离线模型。

## 启用

1. 安装并登录官方 ChatGPT 客户端，开通 Dot，确认客户端里的主 Dot 是要连接的原 Dot，并能正常聊天。
2. 完成 codex-lark 原有的飞书机器人配置。
3. 在运行 codex-lark 的电脑上执行，随后重启桥接：

```bash
npx codex-lark@latest dots init
npx codex-lark@latest
```

指定 profile 时两条命令都加 `--profile <名称>`。从源码运行可使用 `pnpm build` 后的 `node bin/codex-lark.mjs dots init`。

在机器人主人的飞书私聊中点“切换到 Dots”，桥接会核对当前 ChatGPT 账号、主 Dot、原私聊房间和双方身份。没有网页初始化、Tunnel、自定义 MCP 插件、配对码、事件任务或额外常驻程序。不会修改客户端安装包、注入脚本或打开调试端口。

目前仅供机器人主人的一个私聊使用。群聊和其他成员不能连接此 Dot；普通 ChatGPT 聊天不在连接范围。首次连接的账号或主 Dot 变化时，需要明确断开后重新连接，旧收件不会转发给新账号。

## 消息能力

| 方向 | 能力 | 处理方式 |
| --- | --- | --- |
| 飞书 → Dot | 文字 | 发入原会话，保留消息顺序 |
| 飞书 → Dot | 图片 | 下载原图片，上传为原会话附件，由 Dot 理解 |
| 飞书 → Dot | 文件 | 传递原始文件，由 Dot 决定如何读取；桥接不解析或执行文档 |
| 飞书 → Dot | 语音或音频文件 | 阿里云转写文字与原音频一起进入原会话 |
| Dot → 飞书 | 文字 | 等待本轮真正完成后，回复对应的飞书原消息 |
| Dot → 飞书 | 图片、文件 | 下载本轮原生附件并回复同一条飞书消息；音频附件可按文件回传 |

桥接使用原生回合状态通道判断完成，不把“我会生成文件”这类中间进度当作最终答复。仅收集当前输入触发的聊天答复，后台任务通知不会冒充本条飞书问题的答复。审批、其他后台通知和未支持的消息形式仍在客户端处理。

原生主回合结束后，委派任务仍可能稍后往会话里发结果。桥接会在处理窗口内继续检查已回传输入的续答，按原生消息 ID 持久化去重，并回复原飞书消息；返回 Codex 和重启桥接后仍可恢复。出现下一条原生用户输入时，先补齐它之前的遗漏答复，再结束上一条输入的续答检查，避免把下一条问题的答案混入。未携带明确关联的、跨过下一条输入才返回的结果无法可靠归属，仍需在客户端核对。

当前未接入视频和贴纸。传输某种文件不等于 Dot 一定能读取其内容；遇到损坏、受密码保护或 Dot 不支持的文件，以原会话实际答复为准。

## 从 0.3.0 升级到 0.3.1

如果飞书只收到“我会检查 / 我会处理”，而客户端原会话稍后出现了完整结果，请升级桥接。0.3.0 可能在主回合结束后停止收集，遗漏委派任务随后发出的答复。

先停止当前桥接，再使用同一个 profile 启动新版本：

```bash
npx --yes codex-lark@0.3.1
```

使用命名 profile 时追加 `--profile <名称>`；全局安装或源码启动的用户需更新对应安装或 checkout 后重启。已有飞书配置、Dots 绑定、Codex 项目和任务保留，不需要重新扫码、执行 `dots init` 或重新提问。

升级后，在原有 24 小时处理窗口内，程序会核对旧记录中已发送的文字和附件，自动补回能可靠关联的遗漏续答。已过期、已断开绑定或发送结果不确定的记录不会自动重发。旧答复被编辑、删除等原因导致无法确认去重时，会提示核对；不要删除状态文件来强制重试，以免重复发送。

续答检查以原生会话中下一条用户输入为边界。无明确关联且跨过此边界才出现的结果，需要在客户端查看；此版本没有把所有后台通知转发到飞书。

## 可选：阿里云语音识别

原音频可以作为附件进入原会话，但本次真实测试中 Dot 无法直接播放或转写。因此桥接先识别语音，同时保留原音频，便于核对。

在**启动 codex-lark 的进程环境**中配置阿里云百炼 API Key：

```text
DASHSCOPE_API_KEY
```

已有同名环境变量可直接复用。它是百炼模型 API Key，不是飞书 App Secret，也不是阿里云 AccessKey ID / AccessKey Secret。配置后重启 codex-lark；可用 `codex-lark dots status` 检查是否检测到变量。

未配置 Key 时，程序会在下载音频和转交给 Dot 之前回复原飞书消息，说明如何在本机配置 Key、重启并重发；不会要求用户把 Key 粘贴到聊天中。鉴权、额度、格式或网络错误也会给出可操作的提示，不猜测语音内容。

默认使用北京地域的 `qwen3-asr-flash`，通过 HTTPS 将音频直接以 Base64 数据发送到阿里云，不需要 Python、Whisper 模型、ffmpeg、OSS 或语音 SDK。模型调用使用该 Key 对应的阿里云额度。识别结果会注明来源及可能的误差。

使用其他百炼地域或业务空间时，可选配置：

| 环境变量 | 默认值 / 取值 |
| --- | --- |
| `CODEX_LARK_DOTS_ASR_REGION` | 默认 `cn-beijing`；也支持 `ap-southeast-1`，Key 必须属于相同地域 |
| `CODEX_LARK_DOTS_ASR_WORKSPACE` | 可选业务空间 ID；设置后使用该地域的百炼业务空间专属域名 |

参考：[获取百炼 API Key](https://help.aliyun.com/zh/model-studio/get-api-key)、[Qwen-ASR API](https://help.aliyun.com/zh/model-studio/qwen-asr-api-reference)。

**codex-lark 不提供文字转语音（TTS）功能。**生成语音属于 Dot 或其他工具的工作；桥接负责收取输入、必要的语音转写及传递已有答复和附件。此前本地 Whisper、系统 TTS 和 Edge TTS 试验适配不再随包发布。

## 限制与恢复

- 一条输入最多 4 个附件；单个文件最多 20 MiB，图片最多 10 MiB。语音识别的原音频最多 6 MiB、5 分钟，Base64 请求须符合阿里云限制。
- 输入文字与转写合计最多 20,000 字符。飞书文字答复过长时会截短并提示在客户端查看完整内容。
- 一轮最多回传 4 个原生文件，单个文件最多 20 MiB、图片最多 10 MiB。
- 单条输入的处理窗口为 24 小时，最多保留 1,000 条有效或待核对记录。过期收件不会自动发出。
- 输入串行处理。小弟正在原会话处理工作时，新收件排队；原生状态通道中断时等待恢复，不根据消息静默时间猜测完成。
- 等待答复时，如果客户端原会话出现其他人的新输入，会暂停自动关联并提示核对，避免答非所问。
- 原会话或飞书发送中断、结果不确定时，不自动重发；附件准备期间中断则可以恢复，因为此时尚未提交原生聊天消息。

核对结果不确定记录后，可在本人飞书私聊发送 `/dots disconnect`，再点“连接 Dots”。此操作返回 Codex 并建立新绑定；旧收件不会重发。返回 Codex 也可发送 `/codex`。

OpenAI 网络需要代理时，可配置 `CODEX_LARK_DOTS_PROXY`，或沿用 `HTTPS_PROXY`。它只用于固定的 OpenAI HTTPS/WSS 通道与受限文件主机，保留端到端 TLS 校验；不把阿里云音频请求默认转交给该代理。

## 本地数据与兼容性

每个 profile 使用私有 `dots/config.json` 和 `dots/desktop-state.json`。后者包含主人与原会话标识、文字、转写、答复、附件资源标识、请求去重标识和队列状态；不保存登录令牌、阿里云 Key、云端下载凭据或附件正文。临时下载目录在读取后删除，启动时清理中断残留。状态文件使用本机私有权限，但没有应用层加密。

客户端登录令牌只在内存中用于固定 OpenAI HTTPS 主机。原生回合状态使用客户端同样的 `ws.chatgpt.com` 和房间状态通道，短期连接凭据不落盘。回传只接受原会话关联文件和受限 OpenAI 文件主机。

本功能适配客户端内部会话接口，官方未承诺这些接口稳定，升级后需要重新验证。目前真实验收为 macOS ChatGPT 26.1106.51428；Windows 仍需原 Dot 账号实机验收，不能将模拟测试视作 Windows 原会话已打通。

早期未发布的 MCP 事件桥接试验已移除，不再创建本地 MCP 监听端口和服务密钥。旧试验文件不会被程序擅自删除；本机迁移时可停止专用 Tunnel，归档旧事件配置和语音模型，再执行 `dots init`。原生消息历史和 Codex 状态不需要迁移。

## macOS 飞书桌面联调

桌面控制优先使用应用清单中的准确标识 `com.electron.lark`（应用路径 `/Applications/Lark.app`，界面名称“飞书”）。英文名 `Lark` 曾发生连接超时；重建控制会话并使用准确标识后恢复，不据此推断系统权限缺失。

每次窗口或弹窗切换后重新读取状态并使用最新元素编号。中文输入完成后，核对输入框中的完整内容再点击发送按钮；主窗口快捷键不响应时，可用访达与飞书的原生“编辑 → 拷贝 / 粘贴”菜单和当前发送按钮完成附件测试。界面未刷新时，重新搜索并打开自己的机器人私聊核对收件，避免按旧状态重复发送。

常规联调应由操作者在自己的测试机器人私聊完成，使用唯一标记，并恢复原模式；仅登录验证、系统授权或真实手机播放体验等必须依赖用户的环节需要其配合。
